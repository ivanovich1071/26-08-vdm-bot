# Запуск проекта в VS Code

Пошагово, с нуля до работающего бота и виджета. Проверено на Windows 10,
Python 3.13. На macOS и Linux отличаются только команды активации окружения —
они помечены отдельно.

---

## 1. Что понадобится

| Что | Зачем | Где взять |
|---|---|---|
| Python 3.12 или новее | Проект написан на нём | python.org, при установке отметить **Add Python to PATH** |
| VS Code | Редактор | code.visualstudio.com |
| Расширение **Python** (ms-python.python) | Запуск и отладка | Маркетплейс VS Code |
| Расширение **Ruff** (charliermarsh.ruff) | Линтер | Маркетплейс VS Code |
| Токен Telegram-бота | Чтобы бот отвечал | @BotFather в Telegram, команда `/newbot` |
| Ключ Cloud.ru | Чтобы включить модель | Личный кабинет Cloud.ru, сервисный аккаунт |
| Выгрузка 1С (`.xlsx`) | Каталог товаров | От заказчика |

Токен и ключ не обязательны для первого запуска: без токена не поднимется только
Telegram-бот, без ключа Cloud.ru бот работает в режиме поиска по каталогу.

VS Code сам предложит поставить нужные расширения при открытии проекта —
список лежит в `.vscode/extensions.json`.

## 3. Создать виртуальное окружение

Виртуальное окружение изолирует зависимости проекта от системного Python.

Откройте терминал в VS Code: **Terminal → New Terminal** (или `Ctrl+``).

```bash
python -m venv .venv
```

Активировать:

```bash
# Windows, PowerShell
.venv\Scripts\Activate.ps1

# Windows, cmd
.venv\Scripts\activate.bat

# macOS / Linux
source .venv/bin/activate
```

> Если PowerShell ругается на политику выполнения скриптов, разово разрешите
> её для текущего пользователя:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

После активации в начале строки появится `(.venv)`.

**Скажите VS Code использовать это окружение:** `Ctrl+Shift+P` → `Python: Select
Interpreter` → выбрать `.venv`. Без этого запуск по F5 пойдёт мимо окружения.

## 5. Настроить `.env`

```bash
# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env
```

Откройте `.env` в VS Code и заполните то, что есть:

```env
# Токен от @BotFather. Без него Telegram-бот не запустится.
TELEGRAM_TOKEN=123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# Ключ сервисного аккаунта Cloud.ru. Пусто — бот отвечает поиском.
CLOUDRU_API_KEY=

# Куда падают заказы: jsonl (файл) | google_sheets | bitrix24
ORDER_SINK=jsonl
```

`.env` в репозиторий не попадает — он в `.gitignore`. Не коммитьте его и
не присылайте в мессенджерах.

> ⚠️ **Пустой ключ модели — это не «бот чуть хуже», это другой бот.** Без ключа
> разговора нет вовсе: отвечает поиск по каталогу, и на «привет» приходит список
> товаров. Ровно так и случилось 1 сентября — ключи оказались пустыми, и все
> 28 ходов за день прошли поиском. Проверить, что ключ работает:
> `python run.py llm`. В журнале у такого хода стоит `"mode": "search"`.

Если провайдера два и один недоступен, каждый ход платит его таймаутом
(`LLM_TIMEOUT_SECONDS`, по умолчанию 60 с) — пока сбой не запомнится на пять
минут. Работаете без ВПН и Cloud.ru не резолвится — поставьте
`LLM_PROVIDER=openrouter`, и лишнего ожидания не будет.

## 6. Разобрать реестр приказа 1057

Заказчик ведёт соответствие «пункт приказа 1057 → код 1С» сам — на нём построен
его прежний бот «Иван». Файл приходит в PDF (`Baza-Ivan-25-11-25.pdf`), две
колонки: наименование позиции перечня с номером пункта и код товара в 1С.

Шаг необязательный, но сильный: он почти удваивает число товаров, у которых
известен точный пункт перечня. Без него привязка к 1057 остаётся на уровне
документа, без номера позиции.

Порядок обратный привычному — сперва база знаний, потом реестр, потом база
знаний ещё раз: разбору нужен список кодов 1С, чтобы сверить с ним каждую строку.

```bash
python run.py norms --source Baza-Ivan-25-11-25.pdf
```

Ответ на файле от 25.11.2025:

```
строк с кодом 1С: 2476
пунктов приказа:  1127
кодов 1С:         1336
сошлось с выгрузкой: 2108 (85.1%)
нет в выгрузке:      368
```

368 кодов из реестра в текущей выгрузке отсутствуют — реестр от ноября 2025-го,
прайс от августа 2026-го. Это либо снятые с продажи позиции, либо смена кода.
Список печатается в конце, его стоит показать заказчику. В базу знаний такие
строки не попадают: привязка к приказу выдумываться не должна.

Результат — `data/kb/norms_1057.json`, его подхватывает следующий шаг.

### Тексты самих приказов

Реестр даёт номер пункта. Что за этим номером написано, знает только приказ —
и до сих пор не знал никто: чтобы прочитать формулировку, надо было открыть
документ на 147 страницах и найти строку глазами.

Положите рядом с проектом два PDF (в git они не хранятся, как и любые документы
заказчика):

- `ПриказМинпросвещенияРФ-1057.pdf` — детские сады;
- `Об_утверждении_перечня_средств_обучения_и_воспитания,_соответствующих_современным_условиям_обучения,.pdf` — школы, приказ № 838.

```bash
python run.py acts --check
```

Команда разбирает оба документа в `data/kb/norm_items.json` и сверяет с ним
привязки базы знаний. Ожидаемо:

```
приказ № 838: разобрано пунктов — 1873
приказ № 1057: разобрано пунктов — 2600
пунктов в базе знаний: 1199 · не нашлось в приказах: 22
```

Двадцать два — это разрывы страниц в PDF, а не ошибки в данных: номера пунктов
в базе знаний верны. Шаг необязательный. Без него бот называет номер пункта, но
не может привести формулировку из приказа.

## 7. Собрать базу знаний

Без этого шага бот не запустится: каталога ещё нет.

Положите выгрузку 1С в `data/raw/` и выполните:

```bash
python run.py ingest --source data/raw/Pricelist20260826.xlsx
```

В ответ придёт отчёт. Ориентир на текущей выгрузке:

```
товаров: 5936 | с ценой: 5904 | с нормативной привязкой: 3211
из них с точным пунктом перечня: 2057 | по реестру заказчика: 1157
```

Если реестр (шаг 6) не разбирали, привязка будет 2 352 и 1 195 — тоже рабочая,
просто по 1057 без номеров позиций.

Обратите внимание на `open_questions` в конце отчёта — туда попадают
несостыковки данных, которые стоит уточнить у заказчика.

Повторять после каждой новой выгрузки (заказчик присылает 2–3 раза в месяц).

Проверить, что каталог работает, не поднимая бота:

```bash
python run.py search "мячи для спортивного зала в наличии до 2000 руб"
python run.py search "2.20.63"    # пункт приказа 838
python run.py search "1.3.4.5"    # пункт приказа 1057, работает после шага 6
```

## 8. Собрать фотографии товаров (парсер сайта)

В выгрузке 1С изображений нет: там код, наименование, цена, остаток, описание
и ссылка на страницу. Фотографии лежат на сайте, и парсер добирает именно их —
цены и номенклатуру он не трогает, единственный источник по ним остаётся 1С.

Проход собирает три вещи сразу: **адреса** снимков, **сами файлы** снимков и
**характеристики** товара (код 1С, страна, сертификат ЕАС) из блока
`propertyList` на странице.

Для запуска бота шаг не обязателен, но без него **в Telegram фотографий не будет
вообще**. Telegram ходит за картинкой сам, со своих серверов, а оттуда vdm.ru
недоступен — приходит `failed to get HTTP URL content`, и карточка молча уходит
текстом. Виджет в это время фотографии показывает: адрес открывает браузер
посетителя, а он в нормальной сети. Подробный разбор — в `СЦЕНАРИИ_ДИАЛОГА.md`, §5.

Состояние на 01.09.2026: полный проход отработал. Адреса собраны у 4 869 позиций
из 5 936, файлов скачано 7 326 (1,38 ГБ в `data/media/`), характеристики собраны
у 5 932 товаров. Фотографии в Telegram работают.

Повторный запуск дублей не создаёт: и в базе знаний, и в таблицах ключ — код 1С,
запись перезаписывается, а не добавляется. Одинаковые снимки у **разных** товаров
законны — на сайте один файл бывает у нескольких кодов 1С. Одинаковые внутри
папки одного товара убирает `python run.py media --dedupe`.

### Полный проход через VPN с российским IP

С машины вне РФ vdm.ru не открывается, и обход останавливается сам после трёх
подряд неудачных страниц. Порядок запуска, когда доступ появился:

**1. Проверить, что сайт виден именно из окружения проекта** — не из браузера,
браузер может ходить мимо VPN:

```bash
python -c "import urllib.request; print(urllib.request.urlopen('https://vdm.ru/', timeout=10).status)"
```

Ожидаемо `200`. Если здесь ошибка — обход гонять бессмысленно, разбирайтесь с VPN.

**2. Пробный прогон на двадцати карточках** — полминуты:

```bash
python run.py media --cards 20
```

В конце печатается три строки. Смотреть надо на вторую:

```
в кэше: {'products': 5936, 'with_images': 4869, 'images': 9184}
файлы снимков: {'products': 20, 'files': 34, 'bytes': 3218944}
перелито в базу знаний: ...
```

`файлы снимков` с ненулевыми `files` — то, ради чего всё затевается. Если там
нули, файлы не качаются: проверьте, что не стоит `--no-files` и что `MEDIA_ENABLED`
в `.env` не равен `0`.

**3. Основной проход** — весь каталог, около полутора часов:

```bash
python run.py media
```

Прерывать можно смело: `Ctrl+C` сохраняет собранное, повторный запуск продолжает
с места остановки. Уже собранное заново не запрашивается, поэтому второй запуск
пролетает по кэшу мгновенно и упирается ровно в то, что не успели.

**4. Проверить результат:**

```bash
python run.py media --sync
```

Ответ вида `в базе знаний 5936 товаров, с фото 5312 (добавлено 0, всего снимков 9184)`.

Файлы при этом лежат в `data/media/<код 1С>/1.jpg`. Посчитать папки:

```bash
python -c "import pathlib; print(len(list(pathlib.Path('data/media').glob('*'))))"
```

**5. Перезапустить бота.** Соответствие «файл → товар» читается при показе
карточки, но движок собирается один раз при старте — работающий процесс о новых
файлах не узнает.

**6. Проверить в Telegram:** любой запрос → «Подробнее» → должно прийти фото
с подписью. Второй показ того же товара уходит мгновенно: `file_id`, выданный
Telegram при первой отправке, запоминается в таблице `telegram_photos`, и файл
больше не загружается.

> Виджет после этого прохода тоже перестаёт зависеть от vdm.ru: он переключается
> с адреса на сайте на нашу собственную ручку `/media/<код 1С>`.

### Команды в терминале VS Code

Терминал открывается `` Ctrl+` `` (или **Terminal → New Terminal**). Убедитесь,
что в приглашении строки видно `(.venv)` — иначе активируйте окружение:
`.venv\Scripts\Activate.ps1`.

```bash
python run.py media --cards 20
```

Пробный прогон: два десятка карточек, чтобы убедиться, что сайт отвечает и фото
находятся. Занимает полминуты.

```bash
python run.py media
```

Основной проход: весь каталог, 5 936 карточек по одной в секунду — около
полутора часов. Прерывать можно смело: `Ctrl+C` сохраняет собранное, повторный
запуск продолжает с места остановки — то, что уже лежит в кэше, заново
не запрашивается.

Вывод выглядит так:

```
  200 карточек взято из кэша, дальше загрузка с сайта
  340/5936 · с фото 338 · без 2 · загружено 140 · осталось ~93 мин
```

Первая строка важна: до неё обход летит по кэшу мгновенно, после — идёт
по секунде на карточку. Прогресс печатается раз в 15 секунд, а не раз в N
товаров, иначе после быстрого куска наступала бы тишина на час. Оценка времени
считается только по настоящим загрузкам.

Если сайт недоступен, обход не будет молча перебирать тысячи позиций по минуте
на каждую — после трёх подряд неудачных страниц он останавливается сам:

```
Сайт не отвечает: 3 страницы подряд не загрузились.
Обход остановлен, собранное сохранено.
```

```bash
python run.py media --listing https://vdm.ru/catalog/oborudovanie_dlya_detskogo_sada/ --cards 0
```

Быстрый прогрев по странице раздела: одна загрузка отдаёт до трёх десятков
превью 220×200 сразу. Пригодится перед показом, когда полный обход некогда
гонять. Товар сопоставляется по идентификатору Битрикса из выгрузки, промахнуться
позицией невозможно. Позже, при первом показе такой карточки, превью
автоматически заменяется полноразмерным снимком 1200×1200 со страницы товара.

```bash
python run.py media --in-stock
```

Только то, что есть в наличии, — 1 799 позиций вместо 5 936, примерно полчаса.
Разумный компромисс, если полный обход не нужен.

```bash
python run.py media --sync
```

Только перелить накопленное в базу знаний, без единого обращения к сайту.
Обычный прогон делает это сам в конце; отдельная команда нужна, если базу знаний
пересобирали или прогон прервали нештатно.

```bash
python run.py media --no-files
```

Собрать только адреса и характеристики, файлы не качать. Нужно редко: диска
экономит немного, а Telegram без файлов остаётся без фотографий. По умолчанию
файлы качаются.

### Куда сохраняются карточки

Четыре места, у каждого своя роль.

| Где | Что лежит | Зачем |
|---|---|---|
| `data/vdm.sqlite3`, таблица `product_media` | адреса снимков, ETag, дата загрузки, счётчик неудач | Служебный кэш обхода: по нему понятно, что уже забрали, что менять не нужно и к чему больше не возвращаться |
| `data/vdm.sqlite3`, таблица `product_attributes` | характеристики со страницы товара | Код 1С, страна, сертификат ЕАС — их спрашивают в закупке всерьёз |
| `data/media/<код 1С>/1.jpg` | **сами файлы снимков** | Из них шлёт фото Telegram: забрать картинку с vdm.ru он не может. Виджет отдаёт их же через `/media/<код 1С>`. В репозиторий не попадают — в `.gitignore` |
| `data/kb/products.jsonl` | **готовая карточка целиком**, поле `images` | Рабочая база знаний. Из неё живёт бот и в неё смотрит модель |

Пятое место заполняется само, уже в работе: `telegram_photos` — идентификаторы
файлов, выданные Telegram при первой отправке. Второй показ того же товара идёт
по ним, без загрузки вообще.

Формат базы знаний — JSON, по одному товару в строке. Карточка после сбора
фотографий выглядит так (описание сокращено):

### Пересборка базы знаний фотографии не теряет

Новая выгрузка 1С приходит два-три раза в месяц. `run.py ingest` переносит
собранные снимки в новую базу знаний по коду 1С — обход сайта заново гонять
не нужно. В отчёте это видно по полю `with_images`.

### Артикул

Отдельной колонки с артикулом в выгрузке нет: уникальный ключ — `Код в 1с8`,
а вендорские обозначения («ШР», «KBR VIN 82177 K») сидят внутри наименования.
Если нужен настоящий артикул в карточке — пришлите таблицу «код 1С → артикул»
(достаточно двух колонок, XLSX или CSV), поле добавится в карточку и в поиск.

### Настройки сбора

| Переменная в `.env` | По умолчанию | Смысл |
|---|---|---|
| `MEDIA_ENABLED` | `1` | Догрузка фотографий с сайта. `0` — показывать только то, что уже собрано в базе знаний |
| `MEDIA_MIN_INTERVAL` | `1.0` | Секунд между запросами. Единственное ограничение, которое стоит соблюдать: vdm.ru — рабочий сайт с живыми покупателями |
| `MEDIA_USER_AGENT` | `VdmBot/0.1 …` | Как бот представляется сайту |
| `MEDIA_RESPECT_ROBOTS` | `0` | Спрашивать ли `robots.txt`. Он написан для поисковых роботов, а бот делается для владельца сайта |

python run.py widget      # виджет и демо-страница

### Через терминал, оба сразу в одном окне

Так удобнее тестировать: логи обоих каналов идут вперемешку в одну ленту, и
видно, что происходило в виджете, пока отвечал Telegram.

**PowerShell** (терминал VS Code по умолчанию). Виджет уходит фоновым процессом,
но пишет в тот же терминал; бот держит окно:

```powershell
$widget = Start-Process -FilePath .venv\Scripts\python.exe -ArgumentList "run.py widget" -NoNewWindow -PassThru
python run.py telegram
```

Остановить: `Ctrl+C` гасит бота, виджет надо погасить отдельно —

```powershell
Stop-Process -Id $widget.Id
```

Если про `Stop-Process` забыли, порт 8000 останется занятым, и следующий запуск
виджета упадёт. Найти забытый процесс:

```powershell
Get-NetTCPConnection -LocalPort 8000 | Select-Object -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ }
```

**Git Bash, macOS, Linux** — короче и гасит оба разом:

```bash
trap 'kill 0' EXIT; python run.py widget & python run.py telegram
```

`Ctrl+C` останавливает сразу оба процесса.

**Docker** — тоже один терминал, логи обоих сервисов сведены вместе:

```bash
docker compose up --build
```

Годится для показа и для сервера; для разработки медленнее, потому что пересборка
образа занимает время при каждой правке.

> Одного процесса на оба канала нет и не планируется: у виджета и бота разные
> циклы событий, а падение одного не должно уносить второй.

### Журнал диалогов

Пишется автоматически в оба канала, по файлу на сутки в `data/dialogs/`.
Понадобится на этапе доработки промптов.

```bash
python run.py dialogs --last 20                    # посмотреть
python run.py dialogs --channel telegram           # только Telegram
python run.py dialogs --last 50 --export dialogs.md  # выгрузить для работы
```

Персональные данные обезличиваются до записи, ответы на вопросы о контактах
не пишутся вовсе. Отключается через `DIALOG_LOG_ENABLED=0`.

**Сколько стоил разговор.** В каждой записи, где бот обращался к модели, стоит
поле `usage`: провайдер, модель, токены входа и выхода, обращений за ход и
стоимость в рублях. Ход почти никогда не равен одному обращению — сначала вызовы
инструментов, потом ответ, — поэтому расход складывается за весь ход.

```bash
python -c "import json,collections;from pathlib import Path;
s=collections.defaultdict(float);
[s.__setitem__(d['session'], s[d['session']]+d['usage']['cost_rub'])
 for f in Path('data/dialogs').glob('*.jsonl')
 for d in map(json.loads, open(f, encoding='utf-8')) if d.get('usage')];
[print(f'{k}: {v:.2f} руб.') for k,v in sorted(s.items(), key=lambda i:-i[1])]"
```

Так считается стоимость одного пользовательского сценария. Цифры видит только
разработчик — в чат они не выводятся. Цены задаются в `.env`
(`CLOUDRU_PRICE_IN`, `CLOUDRU_PRICE_OUT` и такие же для OpenRouter), по умолчанию
стоят рублёвые цены Cloud.ru за DeepSeek-V4-Flash: 18,53 и 37,08 ₽ за миллион.

**Кто отвечал и почему.** Рядом с `usage` стоит поле `route` — оно нужно, чтобы
на ручном прогоне отличить «бот решил промолчать» от «бот сломался»:

```json
"route": {"role": "sell", "stage": "objection", "objection": "price",
          "objection_handled": false, "routed_by": "модель",
          "cards": {"allowed": false, "reason": "возражение не снято (price)"}}
```

- `role` — `consult` (консультант), `sell` (продавец) или `guard` (защита);
- `stage` — этап разговора: выяснение, показ, возражение, закрытие;
- `objection` — что мешает: цена, норматив, доверие, сроки, документы;
- `routed_by` — `правило` или `модель`. Правилом решается большинство ходов, и
  такой ход обращения к маршрутизатору не стоит;
- `cards.reason` — почему карточки показаны или не показаны.

**Стенограмма прогона.** `--export` собирает разговор в читаемый Markdown и
дописывает в конце итог: ходов, обращений к модели, токенов и рублей. Это то,
что показывают заказчику после прогона по сценарию:

```bash
python run.py dialogs --last 1 --export data/run-01.md
```

## 12. Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `ModuleNotFoundError: No module named 'catalog'` | Окружение не выбрано или зависимости не поставлены | `Python: Select Interpreter` → `.venv`, затем `pip install -e ".[dev]"` |
| `FileNotFoundError: data/kb/products.jsonl` | База знаний не собрана | Шаг 7 |
| `run.py media`: все карточки без фото, `urlopen error` | Нет доступа к vdm.ru с этой машины | Ожидаемо вне РФ. Запускать парсер с виртуалки в РФ |
| `run.py media` идёт слишком долго | Пауза между запросами по секунде на карточку | Так и задумано. Прервать `Ctrl+C`, собранное сохранится; либо `--in-stock`, либо прогрев по разделам через `--listing` |
| `Сайт не отвечает: 3 страницы подряд` | vdm.ru недоступен с этой машины | Обход остановился сам. Продолжить оттуда, где сайт открывается — той же командой |
| Прогресс замер после первых сотен | Кэш кончился, пошли настоящие загрузки | Так и есть: строка «взято из кэша» отмечает переход. Дальше по секунде на карточку |
| В карточке мелкая картинка | Взято превью со страницы списка | Заменится сама при первом показе карточки; либо `python run.py media --cards all` |
| После пересборки базы знаний фото пропали | Пересборка шла старой версией кода | `python run.py media --sync` вернёт их из кэша `data/vdm.sqlite3` |
| **В Telegram карточка без фото, а в виджете фото есть** | Файлы снимков не скачаны: `data/media/` пуста. Telegram ходит за картинкой сам, и с его серверов vdm.ru не открывается | Полный проход §8. Разбор — в `СЦЕНАРИИ_ДИАЛОГА.md`, §5 |
| Фото не появилось и после прохода | Бот запущен до прохода, движок собирается при старте | Перезапустить бота |
| В карточке нет блока характеристик | Характеристики собираются тем же проходом по сайту | Полный проход §8 |
| Фото есть только у карточки «Подробнее» | В выдаче и в ответах ИИ-агента снимков нет по построению | Так и есть, см. `СЦЕНАРИИ_ДИАЛОГА.md`, §5 |
| `Не задан TELEGRAM_TOKEN` | Пустой или неверный `.env` | Проверьте `.env`, перезапустите — он читается при старте |
| `TelegramNetworkError: Cannot connect to host api.telegram.org` | Нет сети или блокировка | Проверьте доступ. На Windows две частые причины уже обойдены в коде: цикл событий по умолчанию и попытка идти по IPv6 |
| `Cloud.ru недоступен: getaddrinfo failed` | Нет доступа в российский сегмент сети | Ожидаемо вне РФ. Бот продолжит работать поиском; для модели нужна виртуалка в РФ |
| **На «привет» приходит список товаров** | Ключа модели нет или он не принят: разговора нет, отвечает поиск по каталогу | Проверить `CLOUDRU_API_KEY` в `.env` и `python run.py llm`. В журнале у такого хода `"mode": "search"` |
| Бот отвечает по делу, но карточек нет | Так и задумано: гейт показа. Карточка появляется, когда известны учреждение и зона и снято возражение | Смотреть `route.cards.reason` в журнале — там написана причина |
| Ход занимает больше двух минут | Недоступный провайдер съедает свой таймаут дважды: у маршрутизатора и у агента | `LLM_PROVIDER=openrouter` либо поднять ВПН, чтобы Cloud.ru отвечал |
| Порт 8000 занят | Другой сервис или прошлый запуск | Смените `WIDGET_PORT` в `.env` или закройте прошлый процесс |
| Виджет открывается пустым | Браузер держит старую версию скрипта | Обновите страницу с `Ctrl+F5` |
| В терминале кракозябры вместо русского | Кодировка консоли Windows | `chcp 65001` перед запуском |
| Ruff подчёркивает весь файл | Расширение не видит `ruff.toml` | Откройте папку проекта, а не отдельный файл |

Остановить сервис: `Ctrl+C` в его терминале либо красный квадрат в панели отладки.
